## [0.1.0] - 2026-11-25

### Added

- Board storage for a host that embeds a board viewer and editor: `AddIyuUBoard(o => o.Boards())` registers `IyuBoardService` over the
  host's `IBoardStore`. A board is an opaque JSON document with an append-only revision history; a save names the revision it worked
  from and a save made on a revision the board has moved past changes nothing and answers `Conflict` with the board as it stands. A
  revision is published by pointing the board at it, every publication and withdrawal adds a line to a history that only grows, and
  `FindLastAcceptedPublicationAsync` walks that history for the newest earlier publication a viewer accepts, since a lower revision
  number is not necessarily one that was ever published. `ListEarlierPublicationsAsync` gives that same list with the documents, for a
  host whose check of a document runs in the browser and not on the server. Rolling a publication back is publishing an older revision.
- The layer is explicit: nothing is registered until `AddIyuUBoard` is called, a call that names no part does not start, and `Boards()`
  without an `IBoardStore` does not start. The message names what is missing.
- The package depends on neither Entity Framework Core nor `Iyu.Core`; `Iyu.UBoard.EntityFrameworkCore` keeps the three tables in the
  application's own `DbContext`.
- The package references the ASP.NET Core shared framework for its routes.
- Board routes: with `Boards()` on, `app.MapIyuUBoard()` also serves the board store under `{prefix}/boards` — make (`POST {id}?name=`, 201 or
  409 with the board that exists), read, save by revision (`PUT {id}?expected=`, 409 with the board as it now stands), rename, delete, the
  revision list and each revision, publish, withdraw, the publication history, the published revision (204 while nothing is published),
  the fallback list, and a paged board list. Bodies are the board as `{ id, name, revision, publishedRevision, document }`. The routes
  need a signed-in caller (or the policy in `IyuUBoardOptions.Policy`) and a same-origin request; a body must be JSON, a value the service
  refuses is 400, a document over 4 MiB is 413, and the history names the caller by name, else by the `sub` claim.
- Who may do what to which board is the application's to say: `IBoardAccess` answers, per person, whether they may view, make, edit, publish or delete a board (`BoardAction`), and is told when a board was just made (`CreatedAsync`) so the application records its owner in its own permission model. Every board route asks it and the answer is enforced there: a board the caller may not view is 404 on every route (it looks like a board that does not exist), a thing they may not do to a board they can view is 403 and changes nothing, a list holds only the boards the caller may view, and a board's answer carries `can: { edit, publish, delete }` so a screen can show it read-only. `GET {prefix}/access` answers `{ create }` for a screen that offers a new-board button. The layer fails closed: `Boards()` without a registered `IBoardAccess` does not start (the message names it); a host with no board-level rules registers `EveryoneSignedInBoardAccess` by name. There is no access store and no sharing screen.
- The board list is a page of what the caller may view, whatever the host hides: `GET {prefix}/boards?skip=&take=` walks the store in id order, leaves out the boards the caller may not view, and stops at `take` of them, so a page is as full as the caller's own boards allow and a host that hides most boards does not give a short page that reads like the end. `skip` is an offset into the store, and `take` counts the boards returned, not the store rows looked at. The body is the array of boards; when the store has more to look at, the answer carries `X-UBoard-Next-Skip` with the offset to ask for next (the offset of the first board the caller may view that this page did not take, or where the look stopped), and leaves the header out when nothing is left. One request looks at no more than 1000 boards, so a caller who may view nothing cannot make it walk an unbounded store: when that bound is reached the page can be short or empty and the header says where to go on. A reader follows the header and not the length of the page: advancing `skip` by `take` instead can show a board on two pages, because a page may reach past the rows `skip + take` counts.
- Ready-made board tables in `Iyu.UBoard.EntityFrameworkCore`: `IyuBoardRow`, `IyuBoardRevisionRow` and `IyuBoardPublicationRow`
  (tables `IyuBoards`, `IyuBoardRevisions`, `IyuBoardPublications`), `ModelBuilder.ApplyIyuBoardTables()` for a context you write,
  `DbContextOptionsBuilder.UseIyuBoardTables()` to add them to a context that is generated and not edited, and
  `AddIyuUBoard<TContext>()` over them, so a host needs no row types of its own. The adapter now references
  `Microsoft.EntityFrameworkCore.Relational` (the mapping names tables).
- A source catalog: `AddIyuUBoard(o => o.Catalog())` adds `GET {prefix}/catalog`, the entities, properties (name, type, nullable, readable,
  and the members of an enum) and links a board can be built from, as the signed-in caller may read them. The port is `IBoardSourceCatalog`,
  which a host implements for the way it serves its data; a host that does not register one does not start. Without `showUnreadable` an
  entity or property the caller may not read is not listed; with it, it is listed and marked not readable, and nothing names the policy.
- `Iyu.UBoard.MainServer`, an adapter in a package of its own (on the shared `Iyu.*` number): `AddIyuUBoardMainServerCatalog()` implements the catalog over the OData
  model of `Iyu.MainServer` and the read policies declared with `Authorize` and `AuthorizeProperty` (or the host's fallback policy), so the
  catalog agrees with what the OData surface would let that caller read.
- An assistant for a board's chat, behind a port: `IBoardAssistant` takes one turn of a conversation about the open board — the conversation so far, the board as stored, and the tools the caller can run — and answers with the tools to run or the assistant's words. The package depends on no model library: the model, its key and the loop that talks to it are an implementation's to provide. A turn is state-free (the history an answer returns is handed back, unread, with the next request) and the tools run where the caller is, as the person, so one question can take several turns. With an implementation registered, `MapIyuUBoard` also serves `POST {prefix}/boards/{id}/turn`; with none the route is not mapped.
- Every turn is asked of `IBoardAccess` before the assistant hears of it. A caller who may not view the board gets 404 whatever they sent; a caller who may view but not edit gets an answer-only turn: a tool the screen did not declare as only reading (`edits: false` on its declaration) is withheld from the assistant, and the answer says `answerOnly: true`. The declaration is the screen's own word, so this keeps the assistant from being offered an edit the person may not make and does not itself stop one — saving a revision is still refused with 403. A board that has not been saved yet is an empty one that its first save would make, so whoever may make boards may start it. A request must be JSON, same-origin and at most 1 MiB (counted as it is read), name at most 32 tools in plain words, and be either a message or the results of the tools the last answer asked for; anything else is 4xx and never reaches the assistant. A failure is answered with its kind only (`BoardAssistantException.Kind`; 429 for `ratelimit`, 502 otherwise) and what the service said stays in the host's log.
- `GET {prefix}/access` answers `{ create, assistant, catalog, dataRoot }`: whether the caller may make boards, whether an `IBoardAssistant` is registered (so a screen leaves its chat out when there is none), whether the source catalog is on, and where the host serves its OData.
- `Iyu.UBoard.IronHive`, an adapter in a package of its own (on the shared `Iyu.*` number): `AddIyuUBoardIronHive(o => { o.BaseUrl = …; o.ApiKey = …; o.Model = … })` registers an `IBoardAssistant` that runs `IronHive.Agent` over a model service reached through IronProw — any OpenAI-compatible service. The address, key, model and the most a reply may take are the host's alone and are set only there (the adapter reads neither the environment nor configuration on its own); a host that names no address or model does not start, and the message names what is missing, never a value. The assistant is asked not to think before it answers, a failure reaches the caller as its kind only (`ratelimit`, `timeout`, `network`, `authentication`, `contextlimit`, `guard`) and cancelling the request ends the turn. The model service is built on a provider of the adapter's own, so it is not the host's `IChatClient`.
- The board screen, carried by the package: `AddIyuUBoard(o => o.Boards().Screen())` and `MapIyuUBoard()` serve `{prefix}/ui` (the boards the caller may open, each with what they may do to it, and a dialog that makes a new one when `IBoardAccess` lets them) and `{prefix}/ui/boards/{id}` (one board: the viewer, the revision history, publishing and rolling back, and — when an `IBoardAssistant` is registered — the assistant's chat, which answers questions or changes the board by talking). The screen shows what the person may do (`can` on each board) and every route still enforces it: a person who may only read a board gets an answer-only chat and no Publish or Restore, a person who may not make boards gets no new-board button. A page is asked of `IBoardAccess` like the board's data: 404 for a person who may not view it, the same 404 as for a board that is not there. `Screen(dataRoot)` names where the host serves its OData (default `/$data`), which the screen's boards read their values from. The screen has no catalog pane: what a person may read is the assistant's to look up.
- The board list renames and deletes: each row has a menu with Rename and Delete, offering only what the host's `can` says the person may do (`edit` for a rename, `delete` for a delete; a row with neither has no menu), and the routes refuse the rest whatever the page shows. A delete asks first and says that the revisions and the publication history go with the board. The list is read a page of 50 boards at a time, and it offers the rest exactly when the host says there is more to look at (see the board list's `X-UBoard-Next-Skip` header above) — a short or even an empty page is not taken for the end, so boards that sit beyond a long run of boards the person may not open are reached.
- What a saved edit drew is read back to the assistant. After a board edit is saved as a revision, the screen draws each part the edit touched the way the viewer does — the same data reads, the same resolution into what the part shows — and returns the result with the answer to the edit, so a model that wrote a total at a pointer the read does not hold, a chart over a field its rows do not have, or a value that comes out 0 although the read holds other numbers sees that while it can still fix it, in the same turn. The answer lists, per part, what it drew (`drew`: a value, the points of a chart and their range, the rows of a table), what is wrong with it and why (`problems`), and the parts whose read matched nothing (`empty`, which is not an error). The model is asked to correct a part that did not draw as intended at most twice in a turn and is told not to edit again after that, so a turn always ends; a look that fails or takes longer than ten seconds leaves the saved edit's answer as it was. The step in the chat says when a part did not draw as intended.
- Every page carries a `Content-Security-Policy` that lets it load only from its own host and run no inline script (`default-src 'none'; script-src 'self'; …; frame-ancestors 'none'`), `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer` and `Cache-Control: no-store`; the files it loads have content-hashed names and are kept for good. The routes keep the same-origin rule of the board routes - a request another site makes (a script, a frame, a fetch) is 403 - with one exception: a person who arrives at one of the two pages by a top-level navigation from another site (a link in a mail, or an identity provider sending them back after sign-in) gets the page. Where the routes are mounted is read from the route the request matched, so `app.MapGroup("/api").MapIyuUBoard()` works. The third-party notices travel with the screen at `{prefix}/ui/third-party-notices.txt` and in the package as `THIRD-PARTY-NOTICES.txt`.
- The screen is built from the web sources in this package's project when it is built, with Node.js 22.12 or later, and embedded in the assembly; nothing built is committed. A build without Node.js still succeeds and says so: such a build has no screen, the host logs that at start, and the screen's routes answer 503 with words that say why (the board routes are not affected). `dotnet pack` refuses to make the package without its screen. `-p:UBoardWeb=false` leaves the screen out on purpose.
- What the screen is made of: `@iyulab/u-board`, `@iyulab/u-board-mcp`, `@iyulab/chat-components`, `@iyulab/components` and `@iyulab/house-style`, at the exact versions the lockfile holds, with React and their dependencies. Every package must be under a permissive licence on an allow-list (MIT, ISC, BSD-2-Clause, BSD-3-Clause, 0BSD, Apache-2.0, and OFL-1.1 for the bundled font), and the build stops, and a test fails, when one is not or when a package has no licence text to ship.
- The board list says who made each board and when it last changed. `BoardSummary` carries `CreatedBy` (who saved the first revision),
  `UpdatedAt` and `UpdatedBy` (when and by whom the current revision was saved) — null when a store does not know — and each entry of
  `GET {prefix}/boards` carries them as `createdBy`, `updatedAt` and `updatedBy`. `Iyu.UBoard.EntityFrameworkCore` reads them from the
  revision table, so no column is added to the board table; a host's own `IBoardStore` can leave them null. The screen's list shows them as
  "Created by" and "Updated". "Created by" is the author of the first revision, not an owner: who owns a board is the host's permission model.
